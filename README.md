# MarketPulse

MarketPulse is a data and intelligence engine for analyzing Iranian social commerce profiles across the Rubino, Telegram, and Bale platforms. It scrapes public profile data, performs offline and AI-powered analysis, and generates client-ready Persian reports (HTML and PDF) with competitive comparison and actionable recommendations.

## Architecture

The pipeline is organized into four sequential phases:

### 1. Scraping Phase
- **Entry**: `main.py` selects a run mode (`mini`/`normal`/`pro`) that determines post count, competitor cap, comments/AI, report type, and packaging; the operator supplies only mode, platform, and target handle(s).
- **Platform scrapers** inherit from `BaseScraper` (`core/base_scraper.py`) and implement `navigate_to_page()` and `scrape_all_posts()`.
- Each scraper produces a CSV (and XLSX) file in `data/` with a consistent schema: `post_index`, `description`, `price`, `engagement`, `comments`.
- **Rubino** uses Selenium with an isolated Chrome profile (`chrome_profile_rubino/`) and requires manual login via `RubikaAuth`.
- **Telegram** and **Bale** use pure HTTP (httpx) against their public web previews, requiring no authentication.

### 2. Analysis Phase
- `MarketAnalyzer` (`core/analyzer.py`) reads the latest CSV for a target and produces a `ProfileInsights` dictionary containing:
  - Engagement statistics (total, mean, median, max, min, std)
  - Top-performing posts and viral outliers (IQR-based)
  - Pricing intelligence (price bands, engagement-weighted average)
  - Product category breakdown via `ProductClassifier`
  - Hashtag frequency and performance
  - Momentum analysis (early vs. recent engagement growth)
  - Offline demand signals (price questions, order intent, complaints via keyword heuristics)
  - AI business intelligence per post (via Groq/LLM, optional)
- `CompetitorComparator` performs head-to-head comparison across multiple profiles and generates strategic advice.

### 3. Report Generation Phase
- `ReportGenerator` (`core/report_generator.py`) consumes the insights dict and produces:
  - A full report (HTML + optional PDF via WeasyPrint) with 11 sections
  - A mini report (~4 pages) covering essential insights only
- Reports are RTL/Persian, styled inline, and use the Vazirmatn font.
- Charts are inline SVG generated by `core/charts.py` (no external charting library needed).

### 4. Packaging Phase
- `ClientPackager` (`core/packager.py`) bundles the report (PDF preferred, HTML fallback), raw Excel data, and competitor data into a timestamped ZIP file in `deliverables/`.

## Key Modules

### `core/base_scraper.py`
Abstract base class (`BaseScraper`) defining the scraper contract:
- `navigate_to_page() -> bool` -- platform-specific page navigation
- `scrape_all_posts(max_posts=None) -> list[dict]` -- extraction logic
- `save_to_csv()` / `save_to_xlsx()` -- universal output with dynamic column detection
- `_convert_persian_nums()` -- normalizes Persian/Arabic digits to ASCII

### `core/analyzer.py`
Contains two classes:
- **`MarketAnalyzer`**: Master analysis method `analyze_profile()` returns a structured insights dict. Supports optional Groq API key for AI comment analysis.
- **`CompetitorComparator`**: `compare()` method produces metrics table, positioning analysis, and actionable advice.

### `core/classifier.py`
`ProductClassifier` with a two-pass design:
1. **Offline scoring**: Token- and phrase-aware keyword/brand matching with Persian suffix stripping. Uses a weighted taxonomy (`TAXONOMY`) and brand dictionary (`BRAND_MAP`).
2. **Optional LLM pass**: Groq API (default model `llama-3.3-70b-versatile`) rescues posts the offline layer could not classify. Batched and cached for efficiency.

### `core/charts.py`
Dependency-free SVG chart generators:
- `bar_chart()` -- horizontal bar chart
- `grouped_bar_chart()` -- vertical grouped bar chart for comparisons
- `donut_chart()` -- donut/pie chart
- `line_chart()` -- line chart with configurable styling

### `core/parsers.py`
Shared, dependency-free text parsers:
- `parse_engagement_text()` -- extracts Toman price, likes, and comments from Persian caption text
- `parse_price()` -- convenience wrapper for price only
- `parse_human_count()` -- parses abbreviated counts (K/M/G/B suffixes)
- `convert_persian_nums()` -- normalizes Persian/Arabic digits to ASCII

### `core/report_generator.py`
Generates bilingual (Persian) reports with 11 sections: cover page, executive summary, KPI cards, engagement trend, category analysis, pricing analysis, hashtag analysis, demand signals, AI business intelligence, competitor comparison, strategic advice, and top posts. Supports both full and mini report modes.

### `core/browser_manager.py`
Manages isolated Chrome profiles per platform to prevent cookie/session overlap. Handles `SessionNotCreatedException` when Chrome is already running.

### `platforms/rubino_scraper.py`
Selenium-based scraper for Rubino (`m.rubika.ir`). Handles dynamic page navigation, post tile detection, comment extraction, and engagement parsing. Includes retry logic for click interception and stale element references.

### `platforms/telegram_scraper.py`
HTTP-based scraper using the public Telegram web preview (`t.me/s/`). Supports pagination via `before=` parameter. Extracts views, reactions, and replies as engagement metrics.

### `platforms/bale_scraper.py`
HTTP-based scraper for Bale (`ble.ir/s/`). No pagination support (fixed recent window). Uses CSS-module prefix matching for stable selectors across front-end builds.

## Setup and Requirements

### Python Dependencies
```
selenium
httpx
beautifulsoup4
openpyxl
weasyprint
numpy
pandas
groq
python-dotenv
telethon        # only for authenticated Telegram scraping (comments)
```
Install everything with `pip install -r requirements.txt`.

### Environment Variables
Create a `.env` file in the project root:
```
GROQ_API_KEY=your_groq_api_key_here

# Optional — authenticated Telegram scraping (reads channel comments over
# MTProto). Create an app at https://my.telegram.org (API development tools).
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=your_api_hash_here
TELEGRAM_PHONE=+98...
```
The Groq API key is optional -- AI comment analysis is skipped when the key is
absent. The Telegram keys are optional too: without them, Telegram falls back to
the anonymous web preview (posts only, no comments). On the first authenticated
run, Telegram sends a login code to the burner account; enter it once and the
session is cached under `auth/` for subsequent runs.

### Chrome Setup
- A ChromeDriver binary must be available in PATH or as `chromedriver.exe` in the project root.
- An isolated Chrome profile directory is created automatically at `chrome_profile_rubino/` for Rubino scraping.
- For Rubino, manual login is required on first run (the scraper detects the login page and prompts for authentication).

## Usage

Runs are driven by a **mode** (product tier), a **platform**, and the target
handle(s). Each mode fully configures the run, so there is no long
questionnaire.

| Mode | Posts | Competitors | Comments/AI | Report | .zip | Use |
|------|-------|-------------|-------------|--------|------|-----|
| `mini` | 15 | 1 max | no | mini | no | Free lead magnet for cold outreach |
| `normal` | 100 | up to 3 | Rubino only | full | no | Paid full report |
| `pro` | all | all | Rubino only | full | yes | Everything the engine can do |

> Comment-based AI analysis runs on platforms whose scraper captures comments.
> **Rubino** always does. **Telegram** does too when MTProto credentials are set
> in `.env` (it reads the linked discussion-group comments via an authenticated
> backend); without credentials it falls back to the anonymous preview and
> comments are skipped. **Bale** exposes no comments (neither its web preview nor
> its native API), so it is preview-only and comment analysis is skipped there.

**Fast path (CLI args, zero prompts):**
```
python main.py <mode> <platform> <client> [comp1,comp2] [saved]
```
- `mode`: `mini` | `normal` | `pro` (or `m` | `n` | `p`)
- `platform`: `r` (rubino) | `b` (bale) | `t` (telegram)
- add a trailing `saved` to reuse the latest saved CSVs instead of scraping

```
python main.py mini b oxostreetwear            # free Bale mini report, scrape fresh
python main.py normal r myshop rival1,rival2   # full Rubino report vs 2 competitors
python main.py pro t oxo comp1 saved           # pro report from latest saved data
```

**Interactive path:** run `python main.py` with no (or partial) args and it
prompts only for what's missing — mode, platform letter, client, competitors,
and whether to scrape fresh or reuse saved data.

## Testing

Run the offline classifier regression tests:
```
python -m pytest tests/test_classifier.py
# or
python tests/test_classifier.py
```

The test suite covers 30+ cases including the original OXO sneaker classification bug, cross-domain coverage (jewelry, watch, perfume, bag, clothing, cosmetics), homonym traps (کیفیت, کتونی, پلاک, ساعت), and pure promotional content.

## Data Schema

All scraped data files follow a consistent CSV schema with these core columns:

| Column | Type | Description |
|---|---|---|
| `post_index` | int | 1-based sequential index |
| `description` | str | Post caption/description text |
| `price` | str | Parsed Toman price (or "None") |
| `engagement` | int | Likes + comments (or views for Telegram/Bale) |
| `comments` | str | Newline-separated comment text |

Platform-specific extra columns (ignored by the analyzer but present in the XLSX):
- Telegram/Bale: `views`, `reactions`, `posted_at`, `post_url`

## Report Output

Reports are generated in `reports/` with filenames following the pattern:
- `{username}_market_report.html` / `.pdf` (full report)
- `{username}_mini_report.html` / `.pdf` (concise report)

Deliverable ZIP packages are created in `deliverables/` with the pattern:
- `{username}_Client_Deliverable_{timestamp}.zip`

## Design Decisions

- **Vazirmatn font**: Embedded via `@font-face` in the HTML so WeasyPrint renders Persian text correctly in PDFs without system font dependencies.
- **SVG charts**: Inline SVG is used instead of matplotlib to keep the dependency footprint minimal and ensure WeasyPrint renders charts natively.
- **Offline-first classifier**: The keyword/brand scoring engine works without any API key. The LLM pass is an optional rescue layer for ambiguous posts only.
- **Isolated Chrome profiles**: Each platform gets its own Chrome profile directory to prevent cookie/session conflicts between runs.
